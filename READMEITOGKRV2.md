# **Метод ближайшего соседа для задачи коммивояжера (TSP)**

**Задача:** найти приближённый маршрут коммивояжёра, посещающий все города ровно один раз и возвращающийся в начальный город, с минимальной общей длиной пути.

**Требования:**
- Дан граф городов с расстояниями между ними
- Начать маршрут из города 0
- Найти гамильтонов цикл минимальной длины
- Вывести порядок посещения городов и общую длину маршрута

**Определение:**
Метод ближайшего соседа - это жадный алгоритм для решения задачи коммивояжера, который на каждом шаге выбирает ближайший непосещённый город, принимая локально оптимальное решение в надежде найти хорошее приближение к глобально оптимальному решению.

## **Принцип работы метода ближайшего соседа для TSP:**

**1. Создается список для хранения маршрута и массив для отслеживания посещенных городов**
```java
List<Integer> path = new ArrayList<>();
boolean[] visited = new boolean[dist.length];
```

**2. Начинаем с города 0 и добавляем его в маршрут**
```java
int curr = 0;
path.add(curr);
visited[curr] = true;
```

**3. Для каждого оставшегося города ищем ближайший непосещённый город**
```java
for (int step = 1; step < dist.length; step++) {
    int nextCity = -1;
    int minDist = Integer.MAX_VALUE;
    
    for (int city = 0; city < dist.length; city++) {
        if (!visited[city] && dist[curr][city] < minDist) {
            minDist = dist[curr][city];
            nextCity = city;
        }
    }
```

**4. Добавляем найденный город в маршрут и обновляем текущий город**
```java
    if (nextCity != -1) {
        path.add(nextCity);
        visited[nextCity] = true;
        curr = nextCity;
    }
}
```

**5. Возвращаем построенный маршрут**
```java
return path;
```  

## **Использованные операторы и функции:**

- `List<Integer> path = new ArrayList<>()` - создание списка для хранения маршрута
- `boolean[] visited = new boolean[dist.length]` - создание массива для отслеживания посещенных городов
- `path.add(curr)` - добавление города в маршрут
- `visited[curr] = true` - отметка города как посещенного
- `for (int step = 1; step < dist.length; step++)` - цикл по оставшимся городам
- `!visited[city]` - проверка, что город не посещен
- `dist[curr][city] < minDist` - сравнение расстояния с текущим минимумом
- `path.add(nextCity)` - добавление следующего города в маршрут
- `visited[nextCity] = true` - отметка следующего города как посещенного
- `return path` - возврат построенного маршрута

## **Дополнительные методы для работы с алгоритмом:**

**Вычисление общей длины маршрута:**
```java
public static int calculateTotalDistance(List<Integer> path, int[][] dist) {
    int total = 0;
    int n = path.size();
    
    // Суммируем расстояния между последовательными городами
    for (int i = 0; i < n - 1; i++) {
        total += dist[path.get(i)][path.get(i + 1)];
    }
    
    // Добавляем расстояние возврата в начальный город
    total += dist[path.get(n - 1)][path.get(0)];
    
    return total;
}
```

**Ввод матрицы расстояний:**
```java
public static int[][] inputDistanceMatrix(Scanner scanner) {
    System.out.print("Введите количество городов: ");
    int n = scanner.nextInt();
    int[][] dist = new int[n][n];
    
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            dist[i][j] = scanner.nextInt();
        }
    }
    return dist;
}
```

## **Временная сложность:**

**Общая временная сложность:** O(n²), где n - количество городов.

**Потому что:**
1) Внешний цикл выполняется (n-1) раз
2) Внутренний цикл на i-й итерации проверяет (n-i) городов
3) Суммарно: (n-1) + (n-2) + ... + 1 = n(n-1)/2 = O(n²) операций

# Дайте определение коэффициента аппроксимации α для задачи минимизации. Что онхарактеризует?
Коэффициент аппроксимации (обозначаемый как α) — это числовая характеристика, которая показывает, насколько хорошо решение, 
найденное приближенным (аппроксимационным) алгоритмом, может отклоняться от оптимального решения задачи оптимизации.

Коэффициент аппроксимации α для задачи минимизации характеризует гарантированное качество работы приближенного алгоритма в худшем случае, показывая, насколько стоимость найденного решения может отклоняться от оптимальной.
Этот коэффициент дает железную гарантию, что для любого входного данных алгоритм найдет решение, стоимость которого не более чем в α раз превышает стоимость идеального оптимального решения.
Чем ближе значение α к единице, тем качественнее считается алгоритм, поскольку его решение оказывается ближе к оптимуму.
Для NP-трудных задач, где поиск точного решения невозможен за разумное время, коэффициент аппроксимации служит ключевой мерой эффективности, позволяя жертвовать точностью ради практической выполнимости вычислений.
